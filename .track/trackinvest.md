## 2. Architecture

- **Single-writer localStorage model**: main key `appHubInvestDb` holds the entire `db` object; `account_overview` uses a separate key `appHubInvestDb_ao` (`{ cards:[], banks:[], pf:[] }`) that is **never** sent to AI. Each page reads the full key, mutates only its slice, writes back merged (data-loss fix in `TRACK.md` #28/#29).
- **Save pattern**: mutate array/object → `saveData()` (rAF-coalesced, `_saveDataPending`) → `safeLocalStorageSet` → `checkStorageQuota` → `broadcastToTabs`.
- **Cross-tab sync**: `BroadcastChannel('trackinvest-sync')`; messages `{ type:'sync-data', data:{ investments|overview|moneyFlow|planner: true } }` → other pages re-read localStorage and re-render.
- **Navigation**: SPA tabs (dashboard/portfolio/ledger) + sheet stack (`openSheet`/`openSubSheet`, scrims, browser back = pop sheet via `history.pushState`). Sub-pages link to each other via top-app-bar icons.
- **AI**: pages hold their own provider keys (encrypted at rest); `callAIProvider(keys, prompt, systemPrompt)` falls back across 5 providers with 2 retries + exponential backoff; `db.aiMemory` caches classification results (comment → category/bucket).
- **Serverless notifications**: service-worker `showLocalNotification` + `db.notifications` in-app store (cap 100, hourly dedupe), generated by `generateScheduledNotifications()`.

### 3.2 Investment entry (`saveInvestment`, app_part2.js:251)
```
{ id, date, type, amount, note, tags, subCategory, broker, growthRate,
  account, isMonthlyContrib, payoutType, investMode, sipDay,
  maturityDate?, interestRate?, units?, mfCode? }
```
- Initial balance is a second entry with note + `' Initial Balance'`.
- Closed (FD renew) entries keep `isClosed, closedDate, closedReason:'Renewed'`; excluded from portfolio math.

### 3.3 Per-category `categoryDetails` fields (`standardFieldConfigs`, app_part1.js:240)
| Category | Extra fields |
|---|---|
| FD | `interest, payout, maturity, broker, subcat` |
| PPF | `interest, maturity, monthly, subcat` |
| PF | `interest, monthly, subcat` |
| SIP | `mf, sipday, monthly, broker, subcat` |
| Stocks | `mf, qty, broker, subcat` |
| Gold / Real Estate | `growth` |
| Cash / Liquid | `simple` |
| Shared | `initialBal, interestRate, fields` |
- `db.categories[type] = { color, icon, is80c }`; default categories `['FD','PPF','PF','SIP','Liquid','Home','Cash','Stocks']` (+ custom).

### 3.4 Account overview (`appHubInvestDb_ao`)
```
{ cards: [{ name, type:'credit'|'debit', bank, cardNumber(last4), cardHolderName,
            expiryMonth, expiryYear, cardNetwork, theme, limit, used }],
  banks: [{ name, accountNumber, balance, ... }],
  pf:    [{ monthlyContribution, employerContribution, interestRate, startDate,
            nominee, notes, accountNumber, balance }] }
```
- `DEFAULT_THEMES = { credit:'midnight', debit:'ocean', bank:'forest', pf:'amber' }`.
- OCR: Tesseract v5 `parseCardOCR` (13–19-digit regex → last4, MM/YY expiry, all-caps name, network guess).

### 3.5 Money flow
```
db.moneyFlow.entries = [{ id, category:'lent'|'borrowed'|'locked'|'uncounted', name, amount, note, createdAt }]
```

### 3.6 Spend tracker
```
db.spendTracker = {
  entries: [{ id, amount, comment, category, date }],        // dedupe by amount+comment+date
  aiCategoryCache: {},                                        // comment -> category
  budget: { needs, wants, investments, mapping }              // legacy migration from dailySpend/fixedExpenses/familyShare/monthlyBudget
}
```
- `DEFAULT_BUDGET_MAPPING`: needs = Food & Dining/Groceries/Bills & Utilities/Rent/Health & Medical/Transport; wants = Entertainment/Shopping/Travel/Education; investments = Investment.
- `CAT_COLORS` fixed map + 32-color `CAT_PALETTE` hash for unknown categories.

## 7. AI Subsystem (migration note)
- Provider router `callAIProvider`: Gemini `gemini-2.5-flash` → Groq `llama-3.3-70b-versatile` → OpenRouter `openrouter/free` → Cerebras `gpt-oss-120b` → GitHub Models `gpt-4o-mini`; 2 retries, exponential backoff; per-provider key regex validation; keys XOR/base64-encrypted at rest (`EX:` prefix), AES when PIN set (`db._ek`).
- Buckwheat already has a JSON-extraction AI client (`keyboard/VoiceAi.kt`, `data/categories/SpendCategorizer.kt`) with centralized `DEFAULT_VOICE_AI_PROVIDER_URL`/`DEFAULT_VOICE_AI_MODEL` (`openai/gpt-oss-20b:free`) in `di/SettingsRepository.kt`. **Reuse that client** for TrackInvest AI; keep the web app's 5-provider fallback as optional later scope.

## 9. Key Migration Risks / Notes
- **Massive scope**: ~19k lines web. Phases are ordered for value: ledger+dashboard first; OCR, WebRTC sync, PWA service-worker, Chart.js PDFs, AI Hub are the biggest re-plumbing and are deferred (web app remains the reference).
- **Data migration**: existing web users can export JSON (`exportData`) and import into the Android app — mirror `restoreData` merge semantics.
- **Currency**: Buckwheat already has INR-default currency infra — reuse.
- **Notifications** in web are serverless/SW-based; Android uses AlarmManager/WorkManager (Buckwheat patterns already exist).
- Keep Buckwheat's existing app untouched; TrackInvest lands as a new module/package so both coexist.
